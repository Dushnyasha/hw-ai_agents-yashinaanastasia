
# Design: Мини-трекер учебных задач

## 1. Архитектура

Приложение реализуется в одном файле `tracker-v2.html`.

Файл содержит:
- HTML — структура интерфейса.
- CSS — оформление и адаптивность.
- JavaScript — данные, обработчики действий, расчёты, валидация и обновление интерфейса.

Внешние библиотеки, CDN и API не используются.

## 2. Модель данных

Каждая задача представлена объектом:

| Поле | Тип | Назначение |
|---|---|---|
| id | string / number | Уникальный идентификатор |
| title | string | Название задачи |
| hours | number | Количество часов |
| done | boolean | Статус выполнения |

Данные хранятся в массиве задач.

Пример начального состояния:

| id | title | hours | done |
|---|---|---:|---|
| 1 | Чтение | 2 | true |
| 2 | Практика | 4 | false |
| 3 | Повторение | 2 | false |

Текущее состояние интерфейса дополнительно содержит выбранный фильтр: `all`, `active` или `done`.

## 3. Изменение данных

### Добавление

1. Получить введённые название и часы.
2. Применить `trim()` к названию.
3. Проверить корректность обоих значений.
4. При ошибке показать сообщение рядом с соответствующим полем, сохранив введённые значения.
5. При успешной проверке создать задачу с уникальным `id` и `done=false`.
6. Добавить задачу в массив.
7. Пересчитать показатели и обновить интерфейс.

### Удаление

1. Определить задачу по `id`.
2. Исключить её из массива.
3. Обновить список и показатели.

### Изменение выполнения

1. Найти задачу по `id`.
2. Изменить `done` на противоположное значение.
3. Обновить список и показатели.

## 4. Валидация

### Название

Допустимо, если:

`title.trim().length > 0`

### Часы

Допустимо, если:
- Значение не пустое.
- Значение преобразуется в конечное число.
- `0.5 <= hours <= 24`.
- `hours * 2` является целым числом.

Примеры:

| Значение | Результат |
|---|---|
| Пустое | Ошибка |
| -1 | Ошибка |
| 0 | Ошибка |
| 0,5 | Допустимо |
| 1 | Допустимо |
| 1,5 | Допустимо |
| 1,3 | Ошибка |
| 24 | Допустимо |
| 24,5 | Ошибка |

Для HTML-поля с типом `number` десятичный разделитель может зависеть от браузера и локали. Логика проверки должна работать с корректным числовым значением, а пустой ввод проверяться до преобразования в число.

## 5. Расчёт показателей

Общие часы:

`totalHours = sum(task.hours for all tasks)`

Выполненные часы:

`doneHours = sum(task.hours where task.done === true)`

Прогресс:

`progress = totalHours > 0 ? Math.round(100 * doneHours / totalHours) : 0`

### Проверка на стартовом примере

- Общие часы: 2 + 4 + 2 = 8.
- Выполненные часы: 2.
- Прогресс: round(100 × 2 / 8) = 25%.

После выполнения «Практики»:

- Общие часы: 8.
- Выполненные часы: 2 + 4 = 6.
- Прогресс: round(100 × 6 / 8) = 75%.

После удаления всех задач:

- Общие часы: 0.
- Выполненные часы: 0.
- Прогресс: 0%.

## 6. Фильтрация

Фильтрация выполняется только при формировании видимого списка.

| Фильтр | Условие |
|---|---|
| Все | Все задачи |
| Активные | done === false |
| Готовые | done === true |

Расчёты `totalHours`, `doneHours` и `progress` используют исходный полный массив независимо от фильтра.

## 7. Интерфейс

Интерфейс содержит:
- Заголовок мини-трекера.
- Подписанное поле названия.
- Подписанное поле часов.
- Кнопку добавления.
- Сообщения об ошибках рядом с полями.
- Переключатель фильтра.
- Список задач с отметкой выполнения и кнопкой удаления.
- Общие часы, выполненные часы и прогресс.

При ширине 390 px элементы должны помещаться в область экрана без горизонтального скролла.

## 8. Необязательное хранение данных

Если реализовано улучшение, используется `localStorage`.

- После изменения задач производится попытка сохранения.
- При запуске производится попытка загрузки.
- Если сохранённых данных нет, используются стартовые задачи.
- Пустой сохранённый массив является корректным состоянием и не заменяется стартовым примером.
- Ошибки доступа к хранилищу не блокируют добавление, удаление и изменение задач.
- При недоступности сохранения пользователь видит сообщение, а приложение продолжает работу в памяти.

При запуске через `file://` поведение `localStorage` зависит от браузера. Постоянное сохранение в таком режиме не гарантируется.

## 9. Ограничения

- Один автономный HTML-файл.
- Без серверной части и внешних зависимостей.
- Без обязательной синхронизации или постоянного хранения.
