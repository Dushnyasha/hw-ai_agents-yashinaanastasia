
# Specification: Weekly Study Tracker

## Requirement 1: Данные задач

Система MUST хранить для каждой задачи:
- `id` — идентификатор задачи.
- `title` — название.
- `hours` — оценка времени в часах.
- `done` — логический статус выполнения.

При первом запуске без ранее сохранённых данных MUST отображаться три стартовые задачи:

1. Чтение — 2 ч, done=true.
2. Практика — 4 ч, done=false.
3. Повторение — 2 ч, done=false.

## Requirement 2: Управление задачами

Система MUST обеспечивать добавление, удаление и переключение статуса выполнения задач.

Все эти операции MUST изменять данные приложения, а не только внешний вид элементов.

### Scenario: Добавление задачи

**WHEN** пользователь вводит корректные название и часы и нажимает кнопку добавления,

**THEN** новая задача появляется в данных приложения и отображается при соответствующем фильтре.

### Scenario: Удаление задачи

**WHEN** пользователь удаляет задачу,

**THEN** задача исчезает из данных приложения, а итоговые показатели пересчитываются.

### Scenario: Переключение статуса

**WHEN** пользователь изменяет статус задачи,

**THEN** значение `done` переключается между `true` и `false`, а прогресс пересчитывается.

## Requirement 3: Валидация

Система MUST проверять:
- Название после `trim()` не является пустой строкой.
- Часы представлены числом.
- Часы находятся в диапазоне от 0,5 до 24 включительно.
- Часы кратны 0,5.
- Пустое значение часов не трактуется как 0.

При ошибке система MUST:
- Не добавлять некорректную задачу.
- Показывать понятное сообщение рядом с соответствующим полем.
- Сохранять введённые значения для исправления.

### Scenario: Пустое название

**WHEN** пользователь отправляет пустое название или только пробелы,

**THEN** задача не добавляется, рядом с полем названия появляется ошибка, введённые данные сохраняются.

### Scenario: Некорректные часы

**WHEN** пользователь отправляет пустые, отрицательные, нечисловые часы, число вне диапазона или число не с шагом 0,5,

**THEN** задача не добавляется, рядом с полем часов появляется ошибка, введённые данные сохраняются.

### Scenario: Граничные значения

**WHEN** пользователь вводит 0,5 или 24 часа с непустым названием,

**THEN** значение считается допустимым.

**WHEN** пользователь вводит 0, 24,5 или 1,3 часа,

**THEN** значение отклоняется с сообщением об ошибке.

## Requirement 4: Расчёт итогов

Система MUST рассчитывать:
- Общие часы по всем задачам.
- Выполненные часы по задачам с `done=true`.
- Прогресс в целых процентах.

Формула:

`progress = round(100 * doneHours / totalHours)`

Если `totalHours = 0`, прогресс MUST быть равен 0%.

Отображение MUST исключать `NaN` и `Infinity`.

### Scenario: Начальное состояние

**WHEN** отображаются три стартовые задачи,

**THEN** всего 8 ч, выполнено 2 ч, прогресс 25%.

### Scenario: Выполнение «Практики»

**WHEN** пользователь отмечает «Практику» выполненной при исходном состоянии остальных задач,

**THEN** выполнено 6 из 8 ч, прогресс 75%.

### Scenario: Пустой список

**WHEN** все задачи удалены,

**THEN** всего 0 ч, выполнено 0 ч, прогресс 0%.

## Requirement 5: Фильтрация

Система MUST поддерживать три фильтра:
- Все — все задачи.
- Активные — `done=false`.
- Готовые — `done=true`.

Фильтр MUST влиять только на отображаемый список.

Итоговые часы и прогресс MUST всегда рассчитываться по всем задачам.

### Scenario: Фильтр активных задач

**WHEN** пользователь выбирает «Активные» в исходном состоянии,

**THEN** отображаются «Практика» и «Повторение», а прогресс остаётся 25%.

### Scenario: Фильтр готовых задач

**WHEN** пользователь выбирает «Готовые» в исходном состоянии,

**THEN** отображается «Чтение», а общие часы остаются равны 8.

## Requirement 6: Интерфейс

Система MUST:
- Иметь подписанные поля и кнопки.
- Оставаться читаемой при ширине экрана 390 px.
- Не создавать горизонтальную прокрутку страницы при такой ширине.
- Отображать ошибки рядом с соответствующими полями.

### Scenario: Узкий экран

**WHEN** приложение отображается на экране шириной 390 px,

**THEN** текст, поля, кнопки и список остаются читаемыми, горизонтальная прокрутка отсутствует.

## Optional Requirement: Сохранение данных

Система MAY сохранять задачи в `localStorage`.

Если улучшение реализовано, система MUST:
- Восстанавливать сохранённые задачи при доступном хранилище.
- Продолжать работу в памяти при недоступном хранилище.
- Показывать понятное сообщение о недоступности сохранения.

При открытии через `file://` сохранение между запусками не гарантируется из-за различий в поведении браузеров.
